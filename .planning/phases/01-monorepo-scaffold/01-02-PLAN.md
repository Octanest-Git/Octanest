<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/client → `/api/rpc` + `/api/rpc/ws` | Untrusted JSON/WS frames; public in Phase 1 |
| Env `OCTANEST_CORS_ORIGINS` → CORS layer | Misconfig can open origins |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Spoofing | RPC version header | mitigate | Middleware requires `Octanest-RPC-Version: 1`; reject otherwise with typed error |
| T-01-04 | Information disclosure | CORS | mitigate | `OCTANEST_ENV=development` allows reflective/any-origin policy; production/Compose requires non-empty `OCTANEST_CORS_ORIGINS` allowlist or API refuses to start |
| T-01-05 | Denial of service | public echo | accept | Phase 1 no auth/rate-limit; echo payload size capped (e.g. max 8KiB) as cheap mitigate |
| T-01-06 | Tampering | generated client | mitigate | `scripts/check-rpc-sync.sh` runs regen + `git diff --exit-code -- packages/api-client` |
</threat_model>

  <action>
Per RESEARCH: use **Axum 0.8 + specta + specta-typescript** with Octanest-owned router (do **not** take rspc as primary dependency).

1. `octanest-core`: define `AppError { code: String, message: String, data: Option&lt;serde_json::Value&gt; }`, `HealthResponse { status: String, version: String }`, `EchoRequest { message: String }`, `EchoResponse { message: String }`. Specta Type derives as needed.
2. `octanest-db`: `Database` wrapper with Postgres URL from `DATABASE_URL`; Phase 1 `ping()` via sqlx (postgres feature). SQLite/MySQL feature flags may exist but need not be proven (Phase 2).
3. `octanest-api`: Axum app binding `API_BIND` (default `0.0.0.0:8080`):
   - `GET /healthz` → 200 JSON `{ "ok": true }` for probes
   - `POST /api/rpc` JSON body `{ "procedure": "system.health"|"system.echo", "input": ... }` returning `{ "ok": true, "data": ... }` or `{ "ok": false, "error": AppError }`
   - `GET /api/rpc/ws` WebSocket: same procedure protocol over messages (D-17 transport only)
   - Middleware: require header `Octanest-RPC-Version` equal to `1` (D-18); on failure return typed error code `rpc.version_mismatch`
   - CORS via tower-http: if `OCTANEST_ENV=development` permissive (reflect origin or allow any with credentials-safe approach); else require `OCTANEST_CORS_ORIGINS` comma-list or exit 1 on boot (D-19/D-20)
4. Procedures: `system.health` returns ok + crate/version string; `system.echo` echoes message (reject if &gt; 8192 bytes).
5. Wire `octanest-db` ping optionally into health payload as `"database": "ok"|"skipped"` without failing health if DB down in Phase 1 — prefer include ping result field but keep HTTP 200 for API liveness; document choice in SUMMARY.
  </action>
